Drop behaviors

drop_behavior decides how many items drop once the chance succeeds. The result always stays inside count (after enchantment bonuses).

TypeCountWhere
uniformAny number from min to max, all equally likely.Mobs, blocks
fixed_rollsStarts at min; a fixed number of independent rolls each add some.Mobs, blocks
chained_rollsStarts at min; keeps adding while rolls succeed, stops at the first failure.Mobs, blocks
max_healthGrows with the mob's max health.Mobs
hardnessGrows with the block's hardness.Blocks
damage_takenGrows with the damage a hit dealt.Mobs, "on": "hit" only

uniform

"count": { "min": 1, "max": 3 },
"drop_behavior": { "type": "uniform" }

1, 2 or 3, each a third of the time. Roll keys (rolls, chance_per_roll, increment_value) are ignored with a warning.

fixed_rolls

"count": { "min": 0, "max": 6 },
"drop_behavior": { "type": "fixed_rolls", "rolls": 3, "chance_per_roll": 0.5, "increment_value": 2 }

The count starts at min. Then rolls rolls are made, each with chance_per_roll; every success adds increment_value. Rolls stop early once the count reaches max, and the result never goes above it. Here: three coin flips worth 2 each, so 0, 2, 4 or 6.

chained_rolls

"count": { "min": 1, "max": 10 },
"drop_behavior": { "type": "chained_rolls", "rolls": 9, "chance_per_roll": 0.5, "increment_value": 1 }

Like fixed_rolls, but the first failed roll ends it. Each extra item is less likely than the one before: here 1 item half the time, 2 a quarter of the time, 3 an eighth, and so on. Good for "usually one, rarely a lot".

Roll settings

All three keys are required for both roll types.

KeyRangeOut of range
rolls0 to max_rolls (1024)0 becomes 1 (warning) unless an enchantment adds rolls; above the limit is clamped.
chance_per_roll0 to 10 is an error unless an enchantment adds roll chance; above 1 is clamped.
increment_value0 to max_increment (1024)0 becomes 1 (warning) unless an enchantment adds increment; above the limit is clamped.

Negative values are errors.

Roll calculator

max_health

For mobs. The count follows the mob's max health:

count = clamp( round( multiplier × function(max_health / divisor) ), count.min, count.max )
"count": { "min": 1, "max": 16 },
"drop_behavior": { "type": "max_health", "function": "log", "multiplier": 3, "divisor": 10 }
  • function: linear (function(x) = x) or log (natural log, function(x) = ln x). Optional, default linear.
  • multiplier, divisor: optional, default 1, must be above 0.
  • count is the clamp: min may be 0, max is the cap.
  • With these numbers: zombie (20 health) → 3 × ln 2 ≈ 2.08 → 2; wither (300) → 3 × ln 30 ≈ 10.2 → 10.

Roll settings and the bonus_roll enchantment bonus are ignored (warning). chance still applies, and a bonus_count enchantment bonus raises the clamp bounds.

hardness

For blocks: same keys and formula, reading the block's hardness (stone 1.5, obsidian 50, ores 3) instead of max health. A hardness of 0 or less (instant-break blocks, bedrock) gives count.min. Hardness values are small, so log is very flat; this behavior is most useful on *, mod:* or tag targets, where one file covers blocks of many hardnesses.

"count": { "min": 0, "max": 10 },
"drop_behavior": { "type": "hardness", "function": "linear", "multiplier": 1, "divisor": 5 }

Stone: 1.5 / 5 = 0.3 → 0. Obsidian: 50 / 5 = 10 → 10.

damage_taken

For mob drops with "on": "hit" only (see Triggers). Same keys and formula, reading the health the hit took: after armor, Resistance and absorption hearts, and never more than the health the mob had before the hit. A hit that deals no damage drops nothing, whatever count.min says.

"on": "hit",
"count": { "min": 1, "max": 20 },
"drop_behavior": { "type": "damage_taken", "function": "linear", "multiplier": 1, "divisor": 1 }

One item per point of damage (half a heart), up to 20.
