Drop files

A drop file adds drops to a mob (mob_drops/) or a block (block_drops/). This page lists every key. Most keys are required on purpose: a file always says exactly what it does.

A complete example

A zombie drop that uses most keys. You will rarely need all of them at once.

{
  "version": 1,
  "entity": "minecraft:zombie",
  "conditions": [
    { "condition": "minecraft:killed_by_player" }
  ],
  "drops": [
    {
      "item": "minecraft:emerald",
      "chance": 0.05,
      "count": { "min": 1, "max": 3 },
      "nbt": "{display:{Name:'\"Ruby\"'}}",
      "drop_behavior": { "type": "fixed_rolls", "rolls": 3, "chance_per_roll": 0.5, "increment_value": 1 },
      "enchant_bonus": [
        { "enchant": "minecraft:looting",
          "on_enchant": { "bonus_chance": { "bonus_chance_per_level": 0.01, "max_bonus_chance": 0.05 } } }
      ],
      "conditions": [
        { "condition": "minecraft:entity_properties", "entity": "this",
          "predicate": { "flags": { "is_on_fire": true } } }
      ],
      "functions": [
        { "function": "minecraft:enchant_randomly" }
      ],
      "id": "ruby",
      "pity": 50,
      "on_drop": { "glow": true }
    }
  ]
}

File keys

versionintegerRequired

File format version. Use 1. A missing or newer version skips the file.

entity / blockstringRequired

entity in mob_drops/, block in block_drops/. A mob or block id, a #tag, mod:* (everything of a namespace) or * (everything). See Targets and conditions.

conditionsarray of loot conditionsOptional

Global conditions: vanilla loot conditions that gate every drop of the file. When one fails, the whole file is skipped for that kill or break.

dropsarray of dropsRequired

The drops to add. A file with drops must not also have removals: drop files and removal files are never mixed.

Drop keys

Keys of each object inside drops.

itemitem idRequired

The item to drop, such as minecraft:diamond. An item of a mod that is not installed skips the drop with a warning, so packs can support optional mods. For an experience drop write "experience": true instead (see Experience drops).

chancenumber, 0 to 1Required

Chance that the drop happens at all: 0.05 is 5%. Above 1 is clamped to 1 with a warning; below 0 is an error. A chance of 0 is only allowed when an enchantment bonus raises it ("drops only with Looting").

count{ "min": int, "max": int }Required

How many items drop when the chance succeeds. Both keys are required. min goes from 0 to max; max up to the server limit max_count (1024 by default). min greater than max is an error. What happens inside the range depends on drop_behavior.

drop_behaviorobjectRequired

How the count is chosen: uniform, fixed_rolls, chained_rolls, max_health (mobs), hardness (blocks) or damage_taken (hit drops). See Drop behaviors.

nbtSNBT stringOptional

Item NBT in the same text format as /give, such as "{display:{Name:'\"Ruby\"'}}". See Loot functions and NBT.

enchant_bonusarrayOptional

Bonuses from enchantments of the held item (Looting, Fortune or any other). See Enchantment bonuses.

conditionsarray of loot conditionsOptional

Local conditions for this drop only. They add to the file's global conditions: the drop happens only when both pass.

functionsarray of loot functionsOptional

Vanilla (or modded) loot functions applied to the dropped stack, in order.

pityinteger ≥ 1Optional

Bad-luck protection: after this many misses in a row, the next roll is forced. See Pity, first drops, per player.

first_kill / first_breakbooleanOptional

Drop once per player, ignoring the chance. first_kill in mob files, first_break in block files.

per_playerbooleanOptional · mobs

Every player who damaged the mob gets their own roll, locked to them.

idstring, [a-z0-9_./-]Optional

A stable name for the drop's progress (pity, first drop), unique in the file. Without it, progress is keyed by the drop's position in the list, so adding a drop above it resets it.

onstringOptional · mobs

What makes the drop happen: death (default), shear, hit, lightning or periodic, with interval or cooldown. See Triggers.

on_drop{ "glow", "run_function" }Optional

Actions when the item lands: make it glow, run a datapack function. See Drop actions.

How a drop is rolled

  1. The file's global conditions are tested once. If one fails, no drop of the file happens.
  2. For each drop, its local conditions are tested.
  3. The chance (plus enchantment bonuses) is rolled.
  4. On success, the count is rolled with drop_behavior inside count.
  5. The stack is created with nbt, then each of functions runs on it.
  6. The item spawns; on_drop runs at the end of that tick.

Pity and first drops change step 3: see their page.

Editor autocomplete

Unknown keys are ignored, so a "$schema" key for editor autocomplete is allowed. A JSON Schema for the format is planned.
