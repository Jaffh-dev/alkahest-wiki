Validation and limits

Every file is checked when datapacks load. Problems never crash the game: they skip as little as possible and are reported in the log and by /alkdrops validate.

Errors and warnings

Error
Something is wrong or missing. The smallest part that contains it is skipped: the whole file (file-level keys), one drop, or one removal entry.
Warning
Something was fixed or ignored: a value clamped into range, a key that has no effect, an id of a mod that is not installed. The rest loads.

Log lines look like this, with the JSON path of the problem:

[alkahestdrops] mypack:zombie_diamond: drops[0].count.max: is 5000, above the limit 1024; clamped to 1024

File-level problems (file skipped)

  • version missing, or newer than this version of the mod supports.
  • entity / block missing, malformed, or the other format's key.
  • Both drops and removals, or neither.
  • A removal file on minecraft:player.
  • on in a block file, or an unknown trigger in a removal file.
  • No valid entry left after skipping the bad ones. When every entry was skipped only because of unknown item ids (an optional mod is missing), it is a warning instead.
  • Invalid JSON.

An unknown target id, or a namespace with nothing registered, also skips the file, but as a warning.

Server config

Per-world limits in <world>/serverconfig/alkahestdrops-server.toml. The file is read again on every /reload.

# Limits of Alkahest Drops files. Values above a limit are clamped with a warning in the log.
# Changes apply on the next /reload.
[limits]
	# Highest rolls of a roll-based drop_behavior, and of its enchantment roll bonus.
	# Rolls run on every kill or block break, so high values cost server time.
	max_rolls = 1024
	# Highest count.min/count.max of a drop, and of its enchantment count bonus.
	max_count = 1024
	# Highest increment_value of a roll-based drop_behavior, and of its enchantment increment bonus.
	max_increment = 1024

Each limit goes from 1 to 1,000,000. Values above a limit are clamped with a warning.

Workflow

  1. Edit a file and run /reload.
  2. /alkdrops validate errors: fix anything skipped.
  3. /alkdrops validate warnings <namespace>: check nothing was clamped by surprise.
  4. /alkdrops drops <target> and /alkdrops simulate ... to confirm the result.
