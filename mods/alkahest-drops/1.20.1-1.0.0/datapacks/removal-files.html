Removal files

A removal file takes drops away from a mob or block: drops of its loot table, drops other mods add, and drops that drop files of other namespaces add. It can also turn off experience.

Example

{
  "version": 1,
  "entity": "minecraft:zombie",
  "removals": [
    "minecraft:rotten_flesh",
    "#minecraft:music_discs",
    { "item": "minecraft:iron_ingot", "conditions": [ { "condition": "minecraft:killed_by_player" } ] },
    { "experience": true, "conditions": [
        { "condition": "minecraft:inverted", "term": { "condition": "minecraft:killed_by_player" } } ] }
  ]
}

Zombies stop dropping rotten flesh and music discs, drop no iron ingot when a player kills them, and give no experience when they are not killed by a player.

File keys

versionintegerRequired

1 for this version.

entity / blockstringRequired

Same targets as drop files: id, #tag, mod:* or *. minecraft:player is not allowed: a player's drops are their inventory.

conditionsarray of loot conditionsOptional

Global conditions: when one fails, nothing in the file is removed.

onstringOptional · mobs

Which trigger's drops the file removes: death (default), shear, hit, lightning, periodic. See Triggers.

removalsarrayRequired

What to remove. Each entry is one of the forms below.

Removal entries

EntryRemoves
"minecraft:rotten_flesh"That item.
"#minecraft:wool"Every item in the item tag.
"*"Every item drop. Experience is not touched.
{ "item": "...", "conditions": [...] }The item (or tag, or *), only when the conditions pass. conditions is required in this form.
{ "experience": true }All experience. conditions is optional.

An unknown item id skips that entry with a warning (the mod may not be installed); the rest of the file still loads.

The namespace rule

A removal file removes drops of the loot table, of other mods, and of drop files in other namespaces. It never removes drops added by drop files in its own namespace.

That rule gives you two things:

  • Replacing a drop is a removal file and a drop file in the same namespace: the removal clears the vanilla drop, your drop file adds the new one, and the removal does not touch it.
  • Packs can undo each other. A modpack's namespace can remove a drop that a mod's drop file adds.

Load order never matters: removals are computed against every loaded file at once.

Example: replace rotten flesh with 3 to 5 rotten flesh

{
  "version": 1,
  "entity": "minecraft:zombie",
  "removals": [ "minecraft:rotten_flesh" ]
}
{
  "version": 1,
  "entity": "minecraft:zombie",
  "drops": [
    {
      "item": "minecraft:rotten_flesh",
      "chance": 1,
      "count": { "min": 3, "max": 5 },
      "drop_behavior": { "type": "uniform" }
    }
  ]
}

Removing experience

{ "experience": true } removes the mob's or block's normal experience and the experience drops of other namespaces, never those of its own namespace. "Set the experience to N" is a removal file with an experience entry plus an experience drop in the same namespace. See Experience drops.

Item entries, even "*", never remove experience.

Removal files and triggers

A removal file applies only to the drops of its on trigger. For shear, hit, lightning and periodic it only removes Alkahest Drops drops of other namespaces: the game's own drops of those actions (sheep wool, chicken eggs) spawn without an event to filter, so they are never removed.

What a removal file cannot remove

Drops a block or mod creates in its own code (outside loot tables), and the drops of a removal file's own namespace. See Known limits.
