Targets and conditions

The target (entity or block) says which mobs or blocks a file is about. Conditions say when its drops happen.

Targets

ValueMatches
"minecraft:zombie"One mob or block.
"#minecraft:skeletons"Every mob in an entity type tag (or block in a block tag).
"twilightforest:*"Every mob or block of one namespace.
"*"Every mob or block. Never players.
  • Several files may target the same mob; their drops all apply.
  • An unknown id, or a namespace with nothing registered, skips the file with a warning: the mod may simply not be installed.
  • Tags are read when the drop happens, so tags from any datapack work.
  • Use the right key: entity in mob_drops/, block in block_drops/. The wrong one is an error that names the right one.

Global and local conditions

Conditions are vanilla loot conditions (the same as in loot tables and predicates). Conditions of other mods work too. They can sit at two levels, in both drop files and removal files:

Global: the file's top-level conditions
Tested once per kill or break. When one fails, the whole file is skipped.
Local: an entry's own conditions
Only for that drop or removal entry.

An entry applies only when the global and the local conditions all pass, like a pool and an entry of a vanilla loot table.

{
  "version": 1,
  "entity": "#minecraft:skeletons",
  "conditions": [
    { "condition": "minecraft:killed_by_player" }
  ],
  "drops": [
    {
      "item": "minecraft:bone_block",
      "chance": 0.1,
      "count": { "min": 1, "max": 1 },
      "drop_behavior": { "type": "uniform" }
    },
    {
      "item": "minecraft:arrow",
      "chance": 1,
      "count": { "min": 2, "max": 4 },
      "drop_behavior": { "type": "uniform" },
      "conditions": [
        { "condition": "minecraft:entity_properties", "entity": "killer",
          "predicate": { "flags": { "is_sneaking": true } } }
      ]
    }
  ]
}

Both drops need a player kill (global). The arrows also need the player to sneak (local).

Real players only

Machine mods (mob grinders, block breakers) use "fake players". Vanilla's killed_by_player passes for them. Alkahest Drops adds two conditions that do not:

  • alkahestdrops:killed_by_real_player for mob files,
  • alkahestdrops:broken_by_real_player for block files.

They work in any loot table too, not only Alkahest Drops files. Fake players also never get pity or first-drop progress.

Silk Touch example (blocks)

{
  "version": 1,
  "block": "minecraft:glass",
  "drops": [
    {
      "item": "minecraft:glass_pane",
      "chance": 1,
      "count": { "min": 2, "max": 2 },
      "drop_behavior": { "type": "uniform" },
      "conditions": [
        { "condition": "minecraft:match_tool",
          "predicate": { "enchantments": [ { "enchantment": "minecraft:silk_touch", "levels": { "min": 1 } } ] } }
      ]
    }
  ]
}
Block drops need a harvesting tool

As in vanilla, a block only drops (and gives experience) when broken with a tool that can harvest it. Stone broken by hand drops nothing, Alkahest Drops drops included.
