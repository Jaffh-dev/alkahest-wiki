Editor autocomplete

Alkahest Drops publishes a JSON Schema for format 1. Editors that understand JSON Schema (VS Code, IntelliJ IDEA, many others) then suggest keys, explain each one on hover, and underline mistakes as you type.

Schema addresses

FolderSchema
mob_drops/https://jaffh-dev.github.io/alkahest-wiki/schemas/alkahest-drops/v1/mob_drops.schema.json
block_drops/https://jaffh-dev.github.io/alkahest-wiki/schemas/alkahest-drops/v1/block_drops.schema.json

Both use shared definitions from common.schema.json in the same folder. The v1 in the path is the file format version, not the mod version: the schema stays the same for every mod version that reads format 1.

Option 1: one line per file

Add "$schema" at the top of a file. The game ignores the key.

{
  "$schema": "https://jaffh-dev.github.io/alkahest-wiki/schemas/alkahest-drops/v1/mob_drops.schema.json",
  "version": 1,
  "entity": "minecraft:zombie",
  "drops": [
    {
      "item": "minecraft:diamond",
      "chance": 0.02,
      "count": { "min": 1, "max": 1 },
      "drop_behavior": { "type": "uniform" }
    }
  ]
}

Option 2: VS Code, for every file at once

Map the folders to the schemas in your workspace settings, so files need no "$schema" line.

{
  "json.schemas": [
    {
      "fileMatch": ["**/data/*/mob_drops/**/*.json"],
      "url": "https://jaffh-dev.github.io/alkahest-wiki/schemas/alkahest-drops/v1/mob_drops.schema.json"
    },
    {
      "fileMatch": ["**/data/*/block_drops/**/*.json"],
      "url": "https://jaffh-dev.github.io/alkahest-wiki/schemas/alkahest-drops/v1/block_drops.schema.json"
    }
  ]
}

Option 3: IntelliJ IDEA

  1. Open Settings → Languages & Frameworks → Schemas and DTDs → JSON Schema Mappings.
  2. Add a mapping with the mob schema URL, schema version 7, and the file path pattern data/*/mob_drops/**/*.json.
  3. Add a second one for the block schema and data/*/block_drops/**/*.json.

What the schema checks

  • Required keys, types and ranges: chance from 0 to 1, whole counts, pity of at least 1.
  • Unknown keys, so typos such as "drop_behaviour" are underlined. The game would silently ignore them.
  • Keys that do not fit together: item with "experience": true, damage_taken without "on": "hit", hardness in a mob file, roll keys on uniform, pity on a drop that can never miss.
  • Drops and removals in the same file, removal files on players, triggers in block files.

What only the game can check

A schema cannot know which ids exist, so run /alkdrops validate after /reload for:

  • Item, mob, block, enchantment, loot condition and loot function ids (vanilla or modded).
  • Whether a run_function exists in a loaded datapack.
  • count.min above count.max, the same enchantment twice, the same id twice.
  • The server limits in alkahestdrops-server.toml.

The drop file generator checks most of these too, against the vanilla ids.
