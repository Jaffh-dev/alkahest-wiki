Pity, first drops, per player

Three ways to make drops fair for each player: pity guarantees a rare drop after a run of bad luck, first_kill / first_break give a drop once, and per_player gives every attacker their own roll.

pity

After pity misses in a row, the roll that reaches the number is forced to drop. Each player has their own counter per drop; any drop resets it.

{
  "item": "minecraft:nether_star",
  "chance": 0.01,
  "count": { "min": 1, "max": 1 },
  "drop_behavior": { "type": "uniform" },
  "id": "rare_star",
  "pity": 50
}

1% per kill, and never more than 50 kills without one: the 50th kill after 49 misses always drops.

  • pity is an integer of at least 1.
  • A pity drop with "chance": 0 drops exactly every N kills.
  • A forced drop gives at least 1 item, rolled with the drop's behavior.
  • A drop that can never miss (chance 1, uniform, count min ≥ 1) gets a warning: pity has no effect.
  • Pity needs a player: it is not counted for kills without one, and not on lightning or periodic drops (warning).

first_kill and first_break

The drop happens once per player, the first time, ignoring its chance. first_kill in mob files, first_break in block files.

{
  "version": 1,
  "entity": "minecraft:wither",
  "drops": [
    {
      "item": "minecraft:beacon",
      "chance": 1,
      "count": { "min": 1, "max": 1 },
      "drop_behavior": { "type": "uniform" },
      "id": "first_wither_beacon",
      "first_kill": true
    }
  ]
}
  • With first_kill, pity is ignored (warning).
  • The other format's key (first_break in a mob file) is ignored with a warning naming the right one.
  • first_kill on lightning or periodic drops is an error: there is no player.

per_player

Mobs only. Every player who damaged the mob gets their own roll, with their own pity, first-kill progress and weapon enchantments. Each drop is locked to its owner: only they can pick it up.

{
  "item": "minecraft:heart_of_the_sea",
  "chance": 0.25,
  "count": { "min": 1, "max": 1 },
  "drop_behavior": { "type": "uniform" },
  "per_player": true
}

If no attacker is online, the drop gets one shared, unlocked roll like a normal drop. per_player is ignored (warning) in block files, on experience drops, and on triggers other than death.

id: keeping progress stable

Progress is saved per player under a key. With an id, the key is mob:<file id>@<id> (or block:...). Without it, the drop's position in the list is used (mob:<file id>#<index>), so inserting a drop above it changes the key and loses the progress.

  • Give every pity or first-drop drop an id.
  • Allowed characters: a-z 0-9 _ . / -. Unique within the file.
  • An id on a drop without pity or first_kill / first_break has no effect (warning).

Where progress lives

  • Saved with the player, kept through death, dimension changes and relogs.
  • Machines' fake players never get progress.
  • Progress of drops that no longer exist is cleaned up on login and /reload. Drops of a file that was skipped by an error keep their progress, so a typo does not wipe it.
  • Reset it with /alkdrops reset <player> [first | pity] [entities | blocks | <target>]. See Commands.
Disabling a datapack

If a datapack is disabled and the world reloads, its players' progress is cleaned up with it.
