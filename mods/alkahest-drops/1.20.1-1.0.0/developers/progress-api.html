Progress API

Read and reset a player's drop progress: pity misses and one-time drops (first_kill and first_break). Useful for quest rewards, server tools and "reroll" items.

Methods

MethodReturns
getPityMisses(Player, String dropKey)int: misses in a row since the drop last dropped.
hasReceivedFirstDrop(Player, String dropKey)boolean: the one-time drop already happened.
resetPity(Player, String dropKey)boolean: there were misses to clear.
resetFirstDrop(Player, String dropKey)boolean: the player had received it.
resetAllPity(Player)int: counters cleared.
resetAllFirstDrops(Player)int: one-time drops forgotten (mobs and blocks).
  • All static on AlkahestDropsApi, server thread only (IllegalStateException elsewhere).
  • Pity and first-drop resets are separate, like /alkdrops reset <player> pity | first: resetting one never touches the other.
  • Machines' fake players have no progress: reads return 0 / false and resets clear nothing.

Drop keys

Progress is stored per drop key, the same key as AddedDrop.dropKey() and OnDropEvent.getDropKey():

  • mob:<file id>@<id> or block:<file id>@<id> for drops with an id, such as mob:mypack:wither_trophy@first_wither_beacon;
  • mob:<file id>#<index> otherwise (the drop's position in drops).

Get keys from the read API rather than building them by hand.

The forced roll happens when the misses reach AddedDrop.pity(), so at most pity - misses rolls are left.

Example: a "lucky charm" that shows the countdown

TargetDrops drops = AlkahestDropsApi.getMobDrops(EntityType.ENDERMAN, DropTrigger.DEATH);
for (AddedDrop drop : drops.drops()) {
    if (drop.pity() == 0) continue;
    int misses = AlkahestDropsApi.getPityMisses(player, drop.dropKey());
    int left = drop.pity() - misses;
    player.displayClientMessage(Component.literal("Guaranteed within " + left + " kills"), true);
}

Example: quest reward that resets a trophy

boolean wasClaimed = AlkahestDropsApi.resetFirstDrop(player, "mob:mypack:wither_trophy@first_wither_beacon");
