Drop files in your mod

A mod's data/ folder is a datapack. Put Alkahest Drops files there and they load when Alkahest Drops is installed, and are simply ignored when it is not. No dependency, no code, no crash.

Where the files go

src/main/resources/
└── data/
    └── mymod/
        ├── mob_drops/
        │   └── frost_golem.json
        └── block_drops/
            └── frost_ore.json

Use your mod id as the namespace. The file format is the same as in datapacks: see the datapack guide.

{
  "version": 1,
  "entity": "mymod:frost_golem",
  "drops": [
    {
      "item": "mymod:frost_core",
      "chance": 0.1,
      "count": { "min": 1, "max": 1 },
      "drop_behavior": { "type": "uniform" },
      "enchant_bonus": [
        { "enchant": "minecraft:looting",
          "on_enchant": { "bonus_chance": { "bonus_chance_per_level": 0.05, "max_bonus_chance": 0.15 } } }
      ],
      "id": "frost_core",
      "pity": 20
    }
  ]
}

Why this is safe

  • Minecraft only reads data folders it knows. Without Alkahest Drops, nobody reads mob_drops/ or block_drops/.
  • Your normal loot tables still work as usual in both cases.
  • Pack makers can override your files with a datapack that has the same path, or remove your drops with a removal file in their own namespace.

Things to keep in mind

The namespace rule
A removal file never removes drops of its own namespace. A removal file in mymod can remove vanilla drops and other namespaces' drops, but not your own drop files; that is what makes "replace a drop" work. Pack makers use their own namespace to remove yours.
Alkahest Drops loot conditions
alkahestdrops:killed_by_real_player and alkahestdrops:broken_by_real_player are fine inside Alkahest Drops files. Do not put them in your regular loot tables unless Alkahest Drops is a required dependency: without it, the condition is unknown and that loot table fails to load.
Items of other mods
An item or target of a mod that is not installed skips that drop or file with a warning, never an error, so files can mention optional mods.
Stable progress
Give every pity or first_kill drop an id, so updating the file never resets players' progress.

Testing

Add Alkahest Drops to your development runtime (see Depending on the API), start a world and use /alkdrops validate mymod and /alkdrops simulate entity mymod:frost_golem 1000.
